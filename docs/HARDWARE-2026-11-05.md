# 別置き拡張と完全復元の実機記録

2026-11-05、対象1個体のKM003C HW2.3／純正2.0.7で確認しました。
利用者が測定側の電源・下流機器を外し、側面HIDだけの接続で更新画面にした状態から実施しました。
シリアル、UUID、校正値、純正バイナリ、TCB／スタックの読み戻しは公開しません。

## 実施した範囲

| 段階 | 結果 |
| --- | --- |
| 通常モードでの事前照合 | loaderと内部 `0x4000..0x7ffff` が元のqualified backupと一致 |
| 手動DFUでの事前照合 | 同じ物理ポート・HW・loaderと内部全領域が一致 |
| 試作の書込み | 462,836バイトの論理イメージ。暗号化転送は462,848バイト。追加消去は `0x74000..0x75fff` の1セクター |
| 書込み後の照合 | loader不変。全内部領域がモデルの期待値に一致。範囲外も一致 |
| 試作の起動 | 通常USBとして再認識し、FW／個体の照合に成功。起動後の内部全領域も一致 |
| GUI接続の観測 | `TASK_GUI` のTCB／スタック範囲を確認し、保存済みR8が `0x74041` と一致（最初の観測で一致） |
| DFUへの復帰 | 既存ライブラリの `jump_to_dfu` で復帰。loaderと内部全領域は不変 |
| 復旧第1段階 | 純正prefix＋FF余白のerase passを適用。追加領域を含む全期待値に一致 |
| 復旧第2段階 | 元のrestore containerを適用。追加セクターを含む内部全領域とloaderが元のbackupに一致 |
| 純正の再起動 | 通常USBへ復帰。起動後の内部全領域も元のbackupに一致 |
| 最終照合 | 通常モードで校正領域1024バイトも元のbackupと一致 |
| 利用者による確認 | 純正の測定画面とボタン操作の復帰を確認 |

試作は、別置きしたGUIコールバックから元のGUI handlerを呼ぶ接続確認用です。
QR APIは含みますが、この実機試験ではQRの生成・液晶表示・本体PD情報取得を呼んでいません。
PD／EPRを維持したQR表示や、電源を接続した計測精度は未確認です。
この接続試作の試験終了時には、元の純正FWと追加領域の消去状態へ復元しました。

## 使ったソフトウェアと照合方法

- `native/overlay207/`：判定処理264バイト、拡張4,084バイト、既存命令の変更は2箇所12バイト。
- `native-host/`：通常上限を維持したまま、既知loader／純正prefixと1追加セクターに限定する専用経路。
- `km003c-lib` の固定版をベースに、既存のパッケージ・暗号化・転送処理を使用。
- パッケージ化後の復元バイト列を照合し、全内部領域のerase／program／metadata commitをモデル化。
- PC上で純正と拡張のscatter-loadを比較し、main直前のSRAM188 KiB全体の一致も確認。

成功した各段階で、全内部領域とloaderのバイナリ読み戻しを非公開で保存しました。
ローカルの記録は `artifacts/overlay207-hardware-*`、最終校正照合は
`artifacts/overlay207-final-stock-check/` にあります。各段階の期待値・SHA-256・成否JSONも保持しています。
生データを含まない公開記録がこの文書です。

この結果は1個体・1回の適用／復元についての観測です。
他のHW／loader、電源断、中断、故障時の復旧や純正機能全体の互換性は保証していません。
使用手順と再現条件は [native-host/README.md](../native-host/README.md) に記載しています。

## 続くQR画面デモの適用

同日の次の段階で、純正画像オブジェクト・入力グループを使うQRデモを適用しました。
測定コネクターを外した同じ接続状態で、既知の純正アプリを全領域照合してから
ソフトウェアでDFUへ切り替えました。切替前後で内部全領域は不変でした。

| 項目 | 観測結果 |
| --- | --- |
| 拡張 | gate 264バイト、QR GUIを含むextension 5,032バイト |
| 書込み | 論理463,784バイト、暗号化転送463,792バイト、消去終端は引き続き `0x76000` |
| 書込み後 | 全内部領域が期待値と一致、loader不変 |
| 起動後 | 通常USB再認識、全内部領域と校正1024バイトが一致 |
| GUI接続 | 保存済みR8が `0x74041` と一致（3回目の読取りで観測） |
| GUIメモリの読み戻し | system layerに非表示の管理オブジェクトとQR画像。画像sourceは240×240／7208バイト |
| QRビット列 | 実機上で生成された1ページ目が、純正画像デコーダーとjsQRで検証したエミュレータ画像に全バイト一致 |
| 利用者の視認 | 本体上でQRを2枚とも表示できたことを確認 |
| iPhone取込と終了操作 | 標準カメラから2枚とも取り込め、Exitで純正画面へ戻れることを利用者が確認 |

初版は固定DEMO ID・全フィールド未取得の2ページです。実測への接続は含みません。
物理LCD上の2ページ表示、iPhoneでの2/2枚取込、Exitによる純正画面復帰を利用者が確認しました。
表示を閉じた後は、書込みなしでDFU経由のアプリ再起動を行い、QRを再表示しました。
試作はスマホでの確認用に起動したままです。操作・メモリ管理・オフライン検証の詳細は
[NATIVE-GUI-207.md](NATIVE-GUI-207.md) を参照してください。

## QRを開き直す操作の追加

続いて、左右同時750 ms長押しでQRを開く版へ更新しました。起動直後は純正画面です。
前の試作bundleと実機の全内部領域を照合し、監査済み旧版からの更新経路を使用しました。
gateは264バイト、extensionは5,288バイト、論理イメージ464,040バイト、暗号化転送464,048バイト。
追加セクターは同じ1個です。書込み後・起動後の全内部領域、loader、校正1024バイトが一致しました。
GUIコールバックは保存済みR8の2回目の観測で確認しました。

利用者が「開く→Exitで閉じる→同じ長押しで再表示」を実機確認しました。
再起動やPC操作は不要です。この段階のQR内容はDEMOです。
記録: `artifacts/shortcut207-{private,bundle,enter-dfu,flash,start}`。

その後、利用者が電源だけを測定入力へ接続し、純正PD検出中と解除後の保存領域を比較しました。
PDO生値は一致しますが、解除後にも値が残るため、単純なRAM読出しでは現状と過去を区別できません。
詳しくは [PD-CACHE-207.md](PD-CACHE-207.md) を参照してください。
検出は解除済みで、解除後VBUSは約0.008 Vでした。電源接続中にフラッシュは更新していません。

## 本体のPDO固定と実測QRへの接続

測定側を両方外したことを利用者が確認した後、PDO固定・TRNGによるID生成を含む版へ更新しました。
途中版のextensionは6,644バイト、論理イメージ465,396バイト、暗号化転送465,408バイト。
loader、書込み後・起動後の内部全領域、校正1024バイトを照合し、GUI入口も最初のR8読取りで確認しました。

- 起動直後の本体RAMでseed準備完了、初期10個の読み捨て、レジスター／クロック復帰済み、capture未準備を確認。
- 利用者が再度電源を接続し、下流負荷なしで既存の純正PDM検出を実行。
- 本体側の所有コピーにSPR 5個／EPR 11個が入り、両方の生値が参照パケットと一致。
- 検出中と解除後のRAMで同じ生値の保持を確認。解除後VBUSは約0.007938 V。
- 終了時の状態切替でIDが一度増える点を発見し、保持条件を修正。最終候補のextensionは6,640バイト。

最終修正版はextension 6,692バイト、論理465,444バイト、暗号化転送465,456バイトです。
測定側が空で側面HIDだけの最新確認後に適用し、書込み後・起動後の全内部領域、loader、
校正1024バイトを照合しました。GUI入口も最初のR8読取りで確認できました。
途中でHIDが抜けた際に、再起動で保持結果が消え、NO DATA画面になることを利用者が確認しました。
利用者がSRCを接続してPDO取得を行い、本体QRからiPhoneへ3枚取り込んだことを報告しました。
提示画像で、3/3枚の完了、取得元KM003C、SPR 5個と予約2枠を含むEPR 11個の表示を確認しました。
固定PDOの電圧・電流、予約枠、AVSの生値が参照結果と一致します。
追加8項目は未要求、capture状態unknownはこの段階の仕様です。
最終版での検出前後のRAM比較によるID保持再確認は未実施です。
確認済み範囲と実装の詳細は [NATIVE-CAPTURE-207.md](NATIVE-CAPTURE-207.md) に記載しています。

## 本体の追加情報取得版へ更新

測定側が両方空・側面HIDだけであることを利用者が改めて確認した後、追加GET候補を適用しました。
extensionは9,428バイト、論理イメージ468,180バイト、暗号化転送468,192バイトです。
追加8KBセクターは2個、消去終端は `0x78000` です。
所有者のloaderを用いたオフライン検証で消去範囲を確認し、2段階の復元モデルも全内部領域で一致しました。

- 更新前のPDO版を全内部バイトで照合し、監査済みの旧bundleから置換。
- 書込み後・起動後の全内部領域、loader、校正1024バイトが期待値に一致。
- 起動後、5回目の保存済みR8読取りでGUI callback `0x74041` を観測。
- 非公開RAMの読取りでTRNGのseed準備、レジスター／クロック復帰、capture未準備を確認。

追加GETの実機確認とiPhone取込は未実施です。通信部分は66件のホスト試験と、
純正logger／enqueue関数を用いるARM試験、純正GUIの待機→5ページ結果→Exit／再表示で確認しています。
実機での復元書込みは以前の1セクター版で実施済みで、今回の2セクター版は復元モデルの検証までです。
ローカル更新ツールはGNU ldで起動時のimport問題を観測し、LLDで再ビルドして正常起動を確認してから使用しました。

非公開記録: `artifacts/info207-{private-05,bundle-05,enter-dfu-05,flash-05,start-05,boot-05,owned-boot-05.json}`。
実装と条件は [NATIVE-INFO-207.md](NATIVE-INFO-207.md) を参照してください。
