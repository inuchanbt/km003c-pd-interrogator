# 本体でPDOを固定し、実データをQRへ渡す

[English](NATIVE-CAPTURE-207.md) · 日本語

以下は実機確認済みのPDO観測版 `26f6250` の記録です。
追加情報の取得を実装した次の候補は [NATIVE-INFO-207.md](NATIVE-INFO-207.ja.md) を参照してください。
既知ハッシュのHW2.3／純正2.0.7に限定します。この観測版の取得対象はSPR/EPR PDOだけです。
Revision、Source Capabilities Extended、Source Info、Statusなどへの追加GET要求は送りません。
それらの項目はQR内でも `not_requested` のままです。

## 操作と保持

1. 起動時は純正画面です。取得結果がなければ、左右同時長押しで開く画面は `NO DATA` です。
2. 検証済みの純正PDM操作でPD検出を行います。本体側が、取得中のSPR/EPR PDOを観測してコピーします。
3. 純正PD検出を閉じても、コピーした最後の結果を本体RAMに保持します。
4. 左右同時長押しで、その結果からQRを生成します。今回の電源は3枚です。
5. Exitで閉じ、再度開いても同じ保持結果・同じIDです。再起動すると保持結果は消えます。

これは取得結果とQRの接続段階です。取得開始を専用ボタンで行う制御や、追加情報要求の接続は別作業です。
現在の実機確認では、PCから既存の純正PDM操作を行い、終了後に本体でQRを開きます。

## 古いキャッシュを採用しない条件

[調査](PD-CACHE-207.ja.md) で、検出終了後も純正RAMのPDO生値とヘッダーが残ることを確認しました。
`native/overlay207/acquire.c` は純正キャッシュから状態と生値を読み取ります。
`capture.c` は次の条件で所有するコピーを更新します。

- observer開始時の既存キャッシュは採用しない。
- 検証した検出中状態 `0x24` だけを対象とし、アイドル時の受信カウンターからの変化を要求する。
- コピー前後で状態、受信カウンター、ヘッダー、EPRフラグが一致することを確認する。
- さらに20 ms以上離れた2回の観測で、メタデータと生バイト列が一致することを要求する。
- 一度採用した受信カウンターのまま、純正処理だけがキャッシュを書き換えても採用しない。
- 新しい受信でも生値が同じなら、受信カウンターだけを更新しIDを維持する。
- SPRは1〜7個、EPRは8〜11個に制限し、4バイト単位の生値をそのまま保存する。
- 新しい検出を観測した時点で旧結果を無効にし、新しい受信がない限り旧キャッシュを採用しない。

終了時のプロトコル状態切替だけでは、保持結果やIDを変更しません。
現在値と誤認しないよう、QRの下端には保持結果を示す `SAVED` を表示します。

コピーはGUI側が所有します。純正PDの割り込みやschedulerを止めません。
QRを開く際にこの所有コピーから転送用データを作り、全ページで固定します。
表示中に新しいPDOを観測しても、開いているQRは途中で差し替えません。

生値の取得状態は `observed`、取得元は `km003c`、capture全体の状態は `unknown` です。
PDヘッダーのrevision bitをGET_Revisionの応答に変換したり、未取得項目を補ったりしません。

## 測定ID

起動後に未使用のTRNGを一度だけ使い、64bitのboot seedを用意します。
新しいセッションまたは異なるPDOを固定するとIDを進めます。単なる再表示では進めません。
機器のシリアル、UUID、校正データはID生成にもQRにも使用しません。

使用条件はTRNGのクロックが停止し、制御レジスターも未使用であることです。
メーカーDDLに従い、256シフト・reload有効で、初期10個の64bit値を読み捨てます。
GUI tickごとに1回だけ完了確認し、1回100 msの期限を超えた場合は中止します。
終了時は制御・モード・クロックを戻し、読戻しで確認してからseedを有効にします。
使用中・タイムアウト・無効な値・復帰失敗では実測QRを作らず `ID ERROR` を表示します。
割り込み、GPIO、ADC、NVICの設定は追加しません。

参照した一次資料:

- [HDSC公式HC32F460 pack 1.0.11](https://github.com/hdscmcu/pack/blob/master/HDSC.HC32F460.1.0.11.pack)
  のレジスター定義。SHA-256 `43ed3801ae30013f1c0008e7be7b70f19acb14cf78cd7233c3e2edcdfebc8173`。
- [メーカーDDLのTRNG実装（固定commit）](https://github.com/zephyrproject-rtos/hal_xhsc/blob/a84e04900616f68097d80cda2e89eaa8af3afadd/hc32_ddl/hc32f460/drivers/src/hc32_ll_trng.c)。
  起動時の読み捨てと出力の扱いを参照。拡張側は非同期・期限付きの処理として実装しています。
- クロック操作には対象純正のFCG0関数 `0x970c` を使用し、その命令と意味も照合しています。

## 検証と限界

54件のテストには、安定待ち、古い値の拒否、検出終了後の保持、新しい検出のID、
QR用コピーの不変性、範囲外・未seed・不明状態の拒否、タイマー周回を含みます。
所有者のROMとGUI RAMを用いるARM検証では、純正キャッシュを消した後でも保持したSPR/EPRから
3枚のQRを生成し、純正画像デコーダーの全出力行をjsQRで復元します。
キーの転送・長押し・Exit・繰返し表示・確保失敗後の復帰も確認します。

`tools/check_gui207.py --rng-mode complete|timeout|busy|zero` でTRNGの周辺モデルを切り替えられます。
このモデルはレジスター復帰と処理の有界性を確認するもので、実際の乱数品質は証明しません。

2回の観測は、任意の競合に対する原子的なPDログの代用ではありません。
未検証の状態番号、観測の間に完了する高速な抜き差し、別電源、異常系での世代判定、
PDタイミングと測定精度全体は未保証です。現段階は対象個体・検証済みPDM経路に限定します。
取得開始と終了を拡張自身が管理する段階で、接続世代と中断の扱いをさらに結び付けます。

## 実機確認の記録

対象1個体では、TRNG初期化・読戻しによる復帰確認まで正常終了しました。
起動直後はcapture未準備で、純正PD検出を実行するとSPR 5個・EPR 11個の所有コピーができました。
検出中と `reset` → `pdm close` 後の両方で、生値が参照パケットに一致しました。
解除後VBUSは約0.008 Vです。

途中版で終了時のプロトコル状態切替だけでもIDが一度増えることを観測し、
保持条件を修正しました。修正後の条件はC／ARMの回帰テスト済みです。
最終修正版は適用・起動後の全領域照合まで実施済みです。
利用者がSRC接続・PDO取得後に本体QRを3枚読み取り、iPhone上で3/3枚の完了を確認しました。
提示画像ではoriginがKM003C、SPRは5個、EPRは予約スロット2個を含む11個です。
固定PDOの電圧・電流、予約枠、およびAVSの生値が参照結果と一致しています。
他の8項目は未要求、capture状態はunknownで、このPDO観測版の仕様どおりです。
終了時のID保持条件はC／ARMで検証済みですが、最終版での検出前後のRAM比較による実機再確認は未実施です。

非公開のRAM記録を照合するには、次のツールを使用します。

```powershell
python tools/check_capture207_live.py --snapshot <private-snapshot-dir> --output artifacts/owned-new.json --compare-fixture
```

今回の参照電源に限り `--compare-fixture` を付けます。起動直後の空状態は `--expect-empty` です。
所有コピー、seed準備、長さ、取得状態を確認し、QRが開いていれば凍結済み転送データとも照合します。
完全RAM／heapと出力レポートは公開しません。

## 単独のUSB-C eMarker検出

純正メニューでUSB-C eMarkerを開き、ケーブルを検出してから左右を同時に長押しします。
純正の単独検出モードで結果表に有効なケーブルIdentityが表示されると、本体に
`CABLE 01/02` が表示されます。左右で2枚を切り替え、Exitで純正画面に戻れます。
結果表のIdHead、CertStat、Product、Cableを4つのVDOとしてそのまま保存します。
4つのVDOがすべてゼロでも、結果表にSVIDがあれば「一部のみ取得」として2枚のQRに保存します。
結果表が未表示、またはIdentityとSVIDの両方が空の場合は `NO DATA` を表示します。

iPhoneの履歴では「ケーブル測定」「電源測定」として、それぞれのIDで開けます。
本体から渡るVDOを使い、ケーブルの種類、VID/PID、生の16進値を表示します。
SVIDのみ取得した場合は、Identity未取得とSVIDの値を表示します。
純正画面のIC名とモード一覧は転送範囲外です。

## SPRの後に届くEPR PDO

追加情報の取得が終わった後も、同じ純正PD検出中にSPRの内容が一致するEPR PDOを受信すると、
保持結果に取り込みます。純正の終了処理で再びSPRへ戻っても、このEPRの記録を保持します。
EPR対応を通知した電源の結果を早めに開くと、純正検出の終了まで、または最長6秒だけ待ちます。
EPR PDOが得られなかった場合はSPRと取得済みの項目を表示し、EPR欄は「一部のみ取得」とします。
すでに表示したQRは固定し、遅れてEPRが届いた場合は、新しく開くQRに更新後の測定IDを使います。
