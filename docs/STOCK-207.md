# 純正2.0.7への追加に向けた調査

2026-11-05。対象HW2.3、通常モードの情報取得でFW2.0.7を確認。
同じ個体の純正バックアップとDFU復旧検証記録を、既存のbackupツールで照合しました。
この段階では本体への書き込みもモード切替も行っていません。

## 解析対象と再現方法

対象アプリのSHA-256は次の値です。同じ版名でもこのハッシュと異なるイメージには
下記アドレスを適用しません。個体のシリアル、UUID、バックアップ本体は公開しません。

```text
c63057eaf08b8625e7ac2fc7270c06d75515e78fdbdd46080bdf4b696984ec67
```

`tools/inspect_stock207.py` に所有者の `stock-app.bin` を渡すと、Unicornで純正の
scatter-load処理 `0x4c48` だけを実行し、main呼出し直前 `0x4c6a` で止めます。
周辺レジスターはマップせず、USB・PD・実機にはアクセスしません。
任意イメージを受け付けるエミュレーターではなく、この既知ハッシュ用の調査です。
Unicorn 2.1.4とCapstone 5.0.7を別途用意してください。

```powershell
python tools/inspect_stock207.py C:\private\stock-app.bin
```

展開後RAM、選択範囲の逆アセンブル、JSONレポートは、git対象外の
`artifacts/stock207-analysis/` に出力します。既存出力は上書きしません。

## 確認した位置

下記は静的解析とPC上の展開処理から得た位置です。関数名・型は推定を含みます。
アドレスはファイルオフセットではなく、実行時アドレスです。

| 処理 | アドレス／観測内容 |
| --- | --- |
| GUIタスク登録 | `0x1100e` で名前TASK_GUI、入口 `0x1ebb1` を渡す |
| GUIループ | `0x1ec04` からhandler候補 `0x39a18`、引数10の待ち関数 `0x4cffc` へ |
| RAM上の液晶転送 | `0x1fff8000`。display driver / area / RGB565へのポインターを受けるLVGL flush相当 |
| バス排他 | オブジェクト `0x1fffb4c4`。取得候補 `0x4cbe6`、解放候補 `0x4ccec` |
| 画素転送 | `0x1fff8110`。画素の2バイトを上位側からQSPIへ送る |
| 完了処理 | 終端で `0x2a696` へ。LVGL flush完了通知に相当する候補 |

液晶と外部NORはQSPIを共有しています。この転送処理はバス排他、QSPI待機、
フラッシュCSの状態確認、LCDの選択と解除を含みます。
QR表示でもこの管理とLVGLの描画サイクルを守る接続が必要です。
LVGLオブジェクトやdisplay driverのポインター、ボタンイベント、画面遷移との接続は未確定です。

## 容量の制約と残作業

取得済みアプリは `0x4000` から456,896バイト、末尾は `0x738c0`。
既存の復旧・独立アプリで扱うアプリ領域の上限 `0x74000` まで1,856バイトしかありません。
新しいCライブラリの容量確認ではtext 5,152バイトなので、そのままの末尾追加では入りません。
この上限外の内部領域や外部NORを、空きと決めつけて保存先にすることはできません。

次に必要なのは、追加処理の配置方法とRAM確保を決め、純正GUIから呼び出す方法を確定することです。
元の資源・展開テーブル・更新／復旧の扱いまで確認した上で、QR画面の試験用パッチを作ります。
それから取得データとの接続、メニューとページ送り、PD／EPRを維持した表示を確認します。

現状は、移植用のQR処理と純正側の位置確認までです。
書き込み可能な純正追加イメージ、本体でのQR表示、実機での読取・PD共存は未確認です。
