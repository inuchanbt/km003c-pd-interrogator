# 本体組み込みの方針

[English](FIRMWARE-INTEGRATION.md) · 日本語

目標は、純正の電圧・電流測定と操作を維持したまま「電源情報を調べる」と
「QRで取り出す」を追加することです。PC側の検証処理と、本体向けCライブラリに加え、
別置き接続試作と専用更新・復旧ツールを実装しました。対象1個体で適用・起動・完全復元を確認済みです。
本体のSPR/EPR PDO保持結果とQR画面を接続しました。追加GET要求と、本体操作からの取得開始は残っています。
本体のQR生成・表示・iPhone読取と、左右同時長押しでの再表示は実機確認済みです。
現在のQR内容は本体で固定したPDOです。純正のPDO保存領域と鮮度の課題は [PD-CACHE-207.md](PD-CACHE-207.ja.md)、
その対処と確認範囲は [NATIVE-CAPTURE-207.md](NATIVE-CAPTURE-207.ja.md) を参照。

## 使える足場

| 資産 | 利用できる部分 | まだ必要な作業 |
| --- | --- | --- |
| KM003C CLI | 純正CDC PDM、任意PD送信、USB受信 | GET_*と純正Policy Engineの共存を実機確認 |
| CH32 Interrogator | 要求順、応答・失敗時の扱い、記録形式の知見 | MCU固有のPHYを分離し、項目の仕様を再確認 |
| DOOM独立実装 | HW2.3での液晶、ボタン、起動・復帰の知見 | 測定・PDは含まないため、純正への追加とは別作業 |
| 公開km003c-firmware | 測定・PDの別実装の参考 | 対象HW2.1と手元のHW2.3の差、PPS/EPR未実装を確認 |

純正FWのソースツリーはこのフォルダにはありません。
対象個体はHW2.3／FW2.0.7と確認しました。次の二案のうち、まず純正への追加を調査しています。

1. 純正アプリの取得済み情報と描画処理を調べ、追加メニュー・呼び出し口を設ける。
   測定機能の維持に近い一方、FWバージョン固有の解析と実機確認が必要。
2. 測定・PDを持つ独立アプリに組み込む。
   ソース上は拡張しやすいが、純正機能一式の再現を伴うため規模が大きい。

この段階でどちらも「完成済みの移植先」と扱わないこと。

## 本体側の機能境界

- PD処理は通信タイミングを守るタスクで実行。QR生成や液晶描画と分ける。
- 情報要求は利用者が開始。進行中の測定・契約との排他を確認する。
- 取得結果に世代番号を付け、QR画面に入る際にコピーを固定する。
- コピーにはPDO・VDOの生値、取得状態、取得元、測定IDを含める。
- QR表示中も必要なPD処理・EPR KeepAlive等を止めない。
- 抜き差し後は旧結果を別測定として保持し、新規取得と混ぜない。
- QRは整数倍率・白地黒・余白付きで描画。向きと輝度を固定して読取試験する。
- 左右ボタンでページを送り、全ページで同じ測定IDを維持する。

当初の301バイトのQRシンボル出力は、液晶描画だけを先に確かめるための入力でした。
現在は本体でDEMOデータからQRを生成・表示できます。測定結果との接続は別作業です。

`native/` には固定コピー、TLV、分割URL、QR生成、RGB565行描画までのC実装を追加しました。
ホスト上とARMエミュレーター上で同じデータを生成し、スマホ用デコーダーで復元できています。
続いて純正GUIとの接続も実装し、実機の2ページ表示・読取・Exit復帰を確認しました。
純正2.0.7のGUIタスクとRAM上の液晶転送位置、末尾追加の容量不足は
[STOCK-207.md](STOCK-207.ja.md) に記録しています。
別置き拡張と純正GUIへの呼出し口の接続試作は [OVERLAY-207.md](OVERLAY-207.ja.md) に記載しています。
純正部分の変更は命令2箇所12バイトで、入口のCRC判定後に拡張か純正のhandlerを選びます。
候補とパッケージは非公開で保持しています。実機確認は
[HARDWARE-2026-11-05.md](HARDWARE-2026-11-05.ja.md) に記録しています。

## 実機で確認する順序

1. HW/FWと現在のアプリ状態を確認。純正環境でPC版のGET_*送受信を採取する。
2. SPR、PPS対応、EPR対応、情報要求非対応の電源で応答と失敗時の復帰を比較する。
3. CH32の取得結果と生値を突き合わせる。別々の測定は同一結果として結合しない。
4. 保存済みQRシンボルを本体液晶へ表示し、複数スマホ・距離・方向・輝度で試す。
5. 純正追加か独立実装かを決定し、情報取得とQR生成を本体で接続する。

現状は通常モードでのUSB/HID/CDC認識、ADC読取、受信専用記録に加え、1個体・1電源で
Revision / Source Capabilities Extended / Status / Source Info / Manufacturer Infoの応答を確認済みです。
純正FWのEPR移行が落ち着くまで待つ処理と、Extended要求の純正PDMによる再構築への対応を追加しました。
本体に載せる処理では、このホスト用コマンド形式をそのままPDの送信データに使わないでください。
標準要求と純正PDMの4バイトへのゼロ埋め変形は別扱いです。
今回の結果は生形式で3枚、HTTPS URL形式で5枚のQRへ変換・復元でき、
後処理後のVBUSも約0.009 Vに戻ることを確認しています。
残る実機確認は電源間の差と、本体の取得制御・結果固定・実測QRとの接続です。
別置き接続試作の書込み用パッケージは生成・実機確認済みです。
完全復元後、元の内部領域とloader、校正1024バイトとの一致を確認しました。
元のバックアップ・復旧資料は上書きしていません。
